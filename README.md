# Пять лабораторных работ по PHP

Репозиторий: [Albekk/polykeklab](https://github.com/Albekk/polykeklab).

Опубликованный сайт: [polykeklab.alwaysdata.net](https://polykeklab.alwaysdata.net/). Размещён 20 ноября 2026; подробности проверки и резервной копии — в TESTING.md. Локальный config.php остаётся конфигурацией локальной тестовой базы; сервер имеет собственный закрытый config.php.

Учебный сайт на PHP 8.2+, PDO и MySQL без фреймворков. Главная объединяет форму обратной связи, записную книжку и три демонстрации общего MVC-блога. Все контакты и статьи в SQL — вымышленные.

## Структура

- `index.php`, `includes/bootstrap.php`, `assets/` — главная, общие функции и оформление.
- `lab1/index.php`, `lab1/headers.php` — POST-форма httpbin и реальный `get_headers()`.
- `lab2/index.php` — единственная точка входа записной книжки; `menu.php`, `viewer.php`, `add.php`, `edit.php`, `delete.php`, `config.php`, `fields.php` — закрытые модули.
- `app/Router.php`, `app/Controllers/`, `app/Views/`, `app/Templates/main.php` — MVC-блог.
- `sql/01_schema.sql`, `sql/02_seed.sql` — схема, 25 контактов, три автора и три статьи.
- `.htaccess`, `router.php` — Apache и локальный PHP-сервер.
- `config.example.php`, `.gitignore` — пример конфигурации и исключения секретов.
- `tests/`, `tools/`, `TESTING.md` — проверки, вспомогательные команды и отчёт.

## Локальный запуск

Нужны PHP 8.2+ с расширениями `pdo_mysql`, `mbstring`, `openssl`, MySQL 5.7+/8.x или совместимая MariaDB. Для `get_headers()` включите `allow_url_fopen` и рабочее хранилище CA-сертификатов. Composer и Node.js не нужны.

1. Создайте отдельную пустую базу с кодировкой utf8mb4 и пользователя с правами SELECT, INSERT, UPDATE, DELETE, CREATE, INDEX, REFERENCES на неё.
2. Импортируйте **сначала** `sql/01_schema.sql`, **затем** `sql/02_seed.sql` через phpMyAdmin или mysql-клиент. Схема не удаляет существующие таблицы. Тестовые данные импортируются один раз: повторный импорт в наполненную базу не нужен.
3. Скопируйте `config.example.php` в `config.php`. Укажите настоящий хост, порт, имя базы, пользователя и пароль. `config.php` исключён из Git.
4. Из корня проекта запустите:

```powershell
php -S 127.0.0.1:8080 router.php
```

Для установленного OSPanel доступен запуск без его необязательных расширений:

```powershell
powershell -ExecutionPolicy Bypass -File tools/serve.ps1
```

5. Откройте `http://127.0.0.1:8080/`. Это адрес локальной проверки; в коде сайта ссылки строятся относительно фактической папки установки.

Без подключения БД работают главная, ЛР1, ЛР3 и ЛР4. ЛР2 и ЛР5 возвращают понятную страницу 503 до настройки MySQL, без раскрытия пароля и текста исключения.

## URL и подпапка

Основные адреса: `/lab1/index.php`, `/lab2/index.php`, `/routing`, `/templates`, `/articles`, `/hello/username`, `/bye/username`, `/articles/1`.

Apache должен читать `.htaccess` и поддерживать `mod_rewrite` (`AllowOverride FileInfo Options Indexes` либо `AllowOverride All`). Реальные файлы и папки обходят MVC-маршрутизацию. Закрытые каталоги и конфигурация запрещены к HTTP-доступу.

Если сайт установлен в `/php-labs`, адрес приветствия будет `/php-labs/hello/username`. Префикс определяется автоматически по точке входа. Если конфигурация прокси этого не позволяет, задайте `'base_path' => '/php-labs'` в `config.php`. Для корня оставьте пустую строку. Домен и localhost в HTML/PHP не зашиты. Для локальной проверки подпапки используйте Apache/OSPanel: `router.php` предназначен для запуска проекта из корня.

## alwaysdata

1. В панели alwaysdata создайте MySQL-базу и пользователя. Возьмите точные значения хоста, имени базы и пользователя из панели: они зависят от аккаунта.
2. Через phpMyAdmin импортируйте два SQL-файла в указанном порядке.
3. Загрузите проект по SFTP/SSH в отдельную папку аккаунта, например `/home/ACCOUNT/www/php-labs`. Не загружайте `.git`, `.runtime`, тесты и инструменты на публичный сайт без необходимости.
4. В разделе сайтов создайте сайт типа **PHP**, выберите PHP 8.2 или новее, укажите загруженную папку в качестве корня и назначьте доступный домен аккаунта. Точные имена пунктов панели могут отличаться.
5. На сервере создайте `config.php` по примеру и заполните данные БД. Ограничьте права на чтение конфигурации владельцем и процессом PHP, не предоставляйте доступ всем пользователям.
6. Проверьте, что `.htaccess` загружен, а сервер разрешает rewrite. Если красивые URL дают 404, проверьте document root и обработку `.htaccess`; не меняйте вслепую глобальные настройки сервера. При ошибке 500 проверьте журнал Apache и доступность директивы Options.
7. Для подпапки поместите весь проект в нужную подпапку действующего PHP-сайта, сохранив `.htaccess` рядом с `index.php`. Проверьте фактический префикс ссылок.
8. Включите HTTPS средствами панели. Проверьте `/config.php` и `/sql/01_schema.sql`: сервер должен отвечать 403. Не публикуйте сайт с доступной конфигурацией или SQL.

Потребуются ваш аккаунт alwaysdata, доступ SFTP/SSH или файловый менеджер, параметры MySQL и репозиторий GitHub. Настройки удалённого сервера и публикация в этой задаче не выполнялись.

## Проверка пяти работ

1. Главная: пять ссылок, логотип, адаптивность, возврат из каждого раздела.
2. ЛР1: обязательные поля, email, три типа обращения, два независимых checkbox; POST прямо на `https://httpbin.org/post`. Только вымышленные данные. На второй странице — заголовки HTTPS или явное сообщение о сетевой ошибке.
3. ЛР2: 25 записей дают страницы 10/10/5. Проверьте все три сортировки, сохранение активных пунктов, добавление, изменение первой/выбранной записи, ошибки полей и удаление. По условию преподавателя удаление выполняет GET-ссылка с токеном сессии: не распространяйте такие ссылки. Для реального сервиса удаление следует перевести на POST.
4. ЛР3: приветствие и прощание, русское имя, неизвестный путь — 404; POST к MVC — 405.
5. ЛР4: `/templates` и `/bye/username` имеют title «Мой блог», `/hello/username` — «Страница приветствия».
6. ЛР5: список и отдельная статья с nickname; отсутствующая статья — 404; автор с NULL после удаления — «Автор не найден». В `ArticlesController::show()` два последовательных запроса: статья, затем автор.

Результаты проведённых проверок находятся в `TESTING.md`. HTTP-тесты запускаются командой `python tests/http_checks.py http://127.0.0.1:8080` при запущенном сервере и подключённой тестовой базе. Они добавляют, изменяют и удаляют только собственный тестовый контакт. Для базовой проверки без БД добавьте `--no-db`.
